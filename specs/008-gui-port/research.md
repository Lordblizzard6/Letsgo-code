# Research — 008 GUI Port

## 1. React + Wails v3 Integration

### How `@wailsio/runtime` Works

Wails v3 provides a JavaScript runtime that bridges the Go backend and the frontend:

```typescript
import { Events, EventsEmit } from "@wailsio/runtime";

// Listen for events from Go backend
Events.on("event-name", (optionalData?: any) => {
    // Handle event
});

// Emit events to Go backend
EventsEmit("event-name", data);
```

### Event Pattern (Backend → Frontend)

The Go backend emits events that the frontend subscribes to:

```typescript
// In App.tsx useEffect:
useEffect(() => {
    const unsubs = [
        Events.on("stream:start", (_, data) => { /* ... */ }),
        Events.on("stream:delta", (_, data) => { /* ... */ }),
        Events.on("stream:end", (_, data) => { /* ... */ }),
    ];
    return () => unsubs.forEach(u => u());
}, []);
```

### Command Pattern (Frontend → Backend)

The frontend calls Go functions through generated bindings:

```typescript
import { Send, Cancel, GetConfig, SaveConfig } from "../bindings";

// Call a Go function
const result = await Send("hello world");
```

The bindings are auto-generated by Wails from Go function signatures. The file `cmd/wails/frontend/bindings/` contains the generated TypeScript.

### Current bindings.ts

```typescript
export * from "../bindings/github.com/user/go-claude-code/cmd/wails/services";
```

This re-exports all Wails-generated service bindings. The actual available functions depend on what's defined in the Go backend.

## 3. Compatibility Issues

### Issue 1: Vite Version Mismatch
- Example uses Vite 7
- Current frontend uses Vite 8
- **Resolution**: No change needed; Vite 8 is backward compatible with Vite 7 config.

### Issue 2: Svelte Dependencies Still in package.json
The current `package.json` still has Svelte-related devDependencies:
- `@sveltejs/vite-plugin-svelte`
- `@testing-library/svelte`
- `@tsconfig/svelte`
- `svelte`
- `svelte-check`

**Resolution**: These can be safely removed in a cleanup step. They don't affect the React build since the Vite config uses `react()` plugin, not `svelte()`.

### Issue 3: DOMPurify Integration
The spec mentions DOMPurify for secure rendering. The current `Markdown.tsx` uses `react-markdown` + `rehype-highlight` without explicit DOMPurify.

**Resolution**: `react-markdown` v10+ sanitizes by default (rehype-sanitize). Verify that `rehype-highlight` doesn't break sanitization. If needed, add `rehype-sanitize` plugin.

### Issue 4: Wails Plugin Config
The current `vite.config.ts` already has:
```typescript
import wails from "@wailsio/runtime/plugins/vite";
plugins: [react(), wails("./bindings")];
```

This is correct for Wails v3. The `wails()` plugin handles:
- Dev server proxy to Wails backend
- Production build output path
- Binding generation

### Issue 5: Go Bindings Generation
The bindings in `cmd/wails/frontend/bindings/` are auto-generated by `wails generate module`. If the Go backend hasn't been built recently, the bindings may be stale.

**Resolution**: Run `wails build` or `wails generate module` before testing the frontend.

## 4. Streaming Architecture

### Current Example Pattern
The example simulates streaming with `setTimeout`:
```typescript
// Simulated streaming
const id2 = setTimeout(() => {
    const reply = { content: "..." };
    setTabs(prev => prev.map(tb => tb.id === targetId ? {...tb, messages: [...tb.messages, reply]} : tb));
}, 1600);
```

### Wails Streaming Pattern
With Wails, streaming works via events:
```typescript
Events.on("stream:delta", (_, data: { text: string }) => {
    // data.text is the incremental chunk
    // Append to the current streaming message
    setTabs(prev => prev.map(tb => {
        if (tb.id !== activeTabId || !tb.streaming) return tb;
        return {
            ...tb,
            streaming: {
                ...tb.streaming,
                text: tb.streaming.text + data.text,
            },
        };
    }));
});
```

### Streaming State Machine
```
IDLE → (user sends) → STREAMING → (stream:end) → IDLE
                  ↘ CANCELLED ↗
                  ↘ ERROR    ↗
```

Events:
- `stream:start` → set busy=true, streaming=true, create placeholder message
- `stream:delta` → append text to placeholder
- `stream:end` → finalize message, set busy=false
- `stream:cancelled` → set busy=false, remove placeholder if empty
- `stream:error` → show error, set busy=false
